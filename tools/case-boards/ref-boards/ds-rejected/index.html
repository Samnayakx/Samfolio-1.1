Why it failed

1
The same blue, written twice

Light and dark were parallel values, not modes of one token, so nothing kept the copies in step.

2
Two collections, no modes

Figma saw two libraries. Switching theme meant swapping files, not flipping a mode.

3
Every new role, added twice

Each token needed a twin in the other file.

What shipped: one semantic collection with Light and Dark as modes. Only the page changes, gray/96 to gray/2.

Why it failed

1
Step numbers say order, not lightness

gray-800 tells you nothing about #242424. The CSS already spoke in HSL lightness.

2
Near-duplicates claimed their own steps

#232323 and #242424 both meant "dark control", so the scale grew in-between steps.

3
Still a class, not a name

Components picked steps directly, so a theme switch meant rewriting classes.

What shipped: grays named by lightness, gray/96 is #F5F5F5. Near-duplicates collapse into one primitive each.

Why it failed

1
Facts and jobs in one list

Raw grays sat beside roles like page, with nowhere to put Light and Dark.

2
A blur doesn't fit in a variable

A shadow is several values at once. A variable is the wrong container for it.

3
Debug colors joined the palette

#FF0000 and #00FF00 got names, so they looked like choices.

What shipped: four collections: primitives, semantic aliases in two modes, dimensions, and effects as styles. Debug colors stay unnamed.
