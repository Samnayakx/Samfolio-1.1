    Work/CotonAI Design System

    Case study ( 03 ) · CotonAI

    One token file that Paper, code and AI agents all build from, with gates that stop it drifting.

    CotonAI's UI took colour from two sources that disagreed. One token file now generates the code, Figma and Paper outputs, and a gate fails on low contrast.

    Role
    Founding Product Designer
    Timeline
    Aug 2025 – Present
    Owned
    Token source, Paper library, rules for agents
    Team
    Co-founder, PM, engineering

    01Context

    A fashion canvas where the interface has to stay out of the work's way.

    CotonAI is an AI canvas for fashion teams. The work on the board is the product, so the interface around it has to stay quiet. I joined as founding product designer in August 2025 and took on the design system. Three groups build with it: designers in Paper, engineers in Tailwind, and AI agents that draft UI code.

    • Problem: Two token sources that disagreed.

      1,411 raw hex values on top of them.

    • Solution: One file generates the rest.

      CSS, Tailwind, Figma and Paper.

    • Outcome: A gate, not a guideline.

      250 contrast pairs pass AA.

    02Diagnosis

    The interface was designed, but nothing enforced the design.

    An audit of src/ on 11 November 2026 found a missing source: colour, size and controls were decided again in every file.

    03Design decisions

    Generate the palette, pin the brand, and let contrast choose the blue.

    Each decision is backed by a number a machine can check.

    What I replacedA token set that wrote the code down instead of correcting it.

    The first token set (57 primitives, 48 aliases) was extracted from the code and described it as it was. The current set is generated and checked against contrast, so it says what the code should be.

    04System architecture

    One source, four layers, every output generated.

    cotonai.tokens.json is the only file edited by hand. npm run tokens generates the CSS variables, Tailwind theme, TypeScript module and Figma import files, and the Paper library is re-pushed from the same JSON. Components use semantic tokens. Primitives only define them.

    Components35, grouped by the job they do.

    • Controls

      Button, Switch, Select, TextField and the rest. Never a bare button with color classes.

    • Overlays

      Dialog interrupts, Popover holds free content, Menu lists actions.

    • Canvas chrome

      Dock, ToolRail, PromptBar and UploadSlot for the board itself.

    DocumentationOne Paper artboard per component.

    • Variants, sizes, states

      Default, hover, pressed, focus and disabled are drawn, not described.

    • A one-line use for

      So the right component is a lookup, not a debate.

    • An AGENTS.md entry

      A component is not done until people and agents can both find it.

    05Applied workflows

    A change goes through one owner, and an agent's draft goes through a person.

    A change starts as an issue naming the two screens that need it. One library owner approves it, the JSON and Paper artboard change together, and an engineer checks it. Agents follow the same rules: they read AGENTS.md, produce a proposal, and a person reviews it.

    ChallengeChanging shapes touches about 106 files. Solution: stage it, and look after each stage.

    Stages

    • 01

      Stage 0, tooling: done

      Generator, token files, baseline.

    • 02

      Stage 1, colours: done

      124 raw hex gone from boardUiTokens.ts.

    • 03

      Stage 2, shapes and sizes

      Radii and control heights. Not started.

    • 04

      Stage 3, roles

      Credits to neutral, menu hover to grey. Not started.

    • 05

      Stage 4, the rest

      Sub-bars, then modals. Not started.

    06Engineering validation

    The gates fail the build, so contrast and drift are not opinions.

    Run on 11 November 2026: the token build is current, every contrast pair passes, and raw colour sits on its baseline. Stage 1 also built with Vite.

    07Measured impact

    Raw colour is falling and contrast passes everywhere it is checked. The rest is not measured yet.

    Only stage 1 is applied, so these are stage 1 numbers.

    • Raw colour: −124

      1,326 to 1,202 literals, all from boardUiTokens.ts

    • Contrast gate: 250/250

      Pairs meet WCAG 2.2 AA, up from 166 checked

    • Colour source: 1 file

      Replaces two that disagreed

    Not measured yetAdoption, time saved and the look in a browser.

    • Adoption

      490 raw buttons unchanged. Stages 2 to 4 not started.

    • Time saved

      No before and after yet.

    • In a browser

      Stage 1 not yet verified.

    LearningA rule a machine can check outlasts a guideline.

    Once contrast became a failing check, two colours had to change: the filled blue and the muted gray. A system is useful in proportion to what it can refuse.

    Limits: the library owner is not yet named, and dark mode in Paper is a token prefix.
